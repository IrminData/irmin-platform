# Security policy

## Reporting a vulnerability

Do not open a public issue for a suspected vulnerability.

Use GitHub's private vulnerability reporting for this repository. If that is
unavailable, contact the Irmin maintainers privately through the organization
contact channel and include:

- the affected project and revision
- reproduction steps or a proof of concept
- expected and observed impact
- any suggested mitigation

Do not include production credentials or personal data in a report.

## Response

Maintainers will acknowledge a complete report, assess severity and affected
versions, coordinate a fix, and disclose it when users can reasonably upgrade
or mitigate. Response timelines depend on severity and reproducibility; this
document does not promise a fixed service-level agreement.

## Supported versions

Security fixes target the current default branch and actively deployed
releases. Older standalone repository histories are retained for reference but
are not independently supported after monorepo cutover.
